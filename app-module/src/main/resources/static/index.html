LoadTest

Очередь и история прогонов. Маршруты LLM задаются во вкладке «Суммаризаторы»: OPENAI — отчёт через summarization-service (часто LiteLLM на :4000), EXTERNAL — отчёт во внешнем контуре (push/callback), без LiteLLM.

Отчёт можно получить через LiteLLM или без него (внешний контур): при перезапросе отчёта выберите маршрут из группы «Внешний контур». Если группы нет, создайте маршрут с провайдером EXTERNAL в «Конфигурация → Суммаризаторы».

Файл и команда — как раньше. Если нужен текстовый отчёт, выберите маршрут LLM: в списке видно провайдер — OPENAI · через summarization (LiteLLM и др.) или EXTERNAL · внешний контур. Для LiteLLM-ветки в конфиге задаются base URL без /v1/... и model id (например loadtest-summary).

Несколько профилей могут указывать на один и тот же демон (пустой URI) — тогда отличаются лимиты и число параллельных прогонов.

Простая форма: несколько HTTP-запросов по очереди после теста. Формат совпадает с JSON Schema на сервере. В URL и query — плейсхолдеры {testStartTimeMs} и {testEndTimeMs}.

Колонка Провайдер: OPENAI — summarization-service (POST {baseUrl}/v1/chat/completions, часто LiteLLM; ключ — env в summarization, не в браузере). EXTERNAL — полный URL приёма пакета в поле Base URL (ingest, POST JSON); после метрик пакет уходит туда, ответ received, затем контур вызывает POST …/external-llm/summary. Включение/выключение — чекбокс «Включён» у маршрута.
