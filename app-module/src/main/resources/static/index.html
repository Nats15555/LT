Файл сценария нагрузки, который будет смонтирован в контейнер как /mnt/test/{fileName}.

Расширение файла должно соответствовать выбранному инструменту. При загрузке выполняется проверка по списку допустимых расширений из конфигурации инструмента (вкладка «Конфигурация» → «Инструменты»).

Типовые соответствия:

  • Locust — .py
  • K6 — .js
  • JMeter — .jmx

Для выбранного инструмента: — выберите инструмент —
Файл не выбран

CLI-команда запуска нагрузочного инструмента в Docker-контейнере. Перед стартом система подставляет плейсхолдеры в фигурных скобках.

{fileName} — имя загруженного файла сценария (например locustfile.py, script.js).

{reportBaseName} — уникальное имя отчёта для этого прогона. Используйте в путях артефактов: /mnt/reports/{reportBaseName}.html, …/{reportBaseName} для CSV Locust/JMeter.

{metricsBaseName} — то же базовое имя для файлов метрик инструмента (если пишете их в /mnt/metrics/…). Обычно совпадает с {reportBaseName}.

Стандартные каталоги в контейнере: /mnt/test — сценарий, /mnt/reports — отчёты, /mnt/metrics — метрики инструмента. Файлы с {reportBaseName} или {metricsBaseName} в команде собираются в артефакты прогона.

Пример (Locust):

locust -f /mnt/test/{fileName} --headless -H http://test-app-1:8080 -u 10 -r 2 -t 60s --html /mnt/reports/{reportBaseName}.html --csv /mnt/reports/{reportBaseName}

Адрес в -H / --host должен открываться из контейнера теста (та же Docker-сеть, например test-app-1:8080).

Планируемая длительность нагрузочного прогона. Значение сохраняется вместе с задачей и отображается в очереди и истории; при перезапуске из истории подставляется снова.

Задаётся в секундах — целое число, не меньше 1. Например: 60 для минуты, 90 для полутора минут.

Укажите длительность, близкую к параметру в CLI-команде: Locust -t 60s → 60, k6 --duration 90s → 90, JMeter — время из плана теста в секундах.
сек

Если галочка включена, после прогона модуль сбора метрик выполнит HTTP-запросы к Prometheus, Elasticsearch и другим API. Ответы сохраняются в истории прогона и используются при суммаризации.

В URL и query допускаются плейсхолдеры {testStartTimeMs} и {testEndTimeMs} — подставляются по времени начала и окончания теста.

Пример metricsConfig:

{
  "delaySeconds": 5,
  "requests": [
    {
      "name": "prometheus",
      "method": "GET",
      "url": "http://prometheus:9090/api/v1/query",
      "queryParams": "query=up"
    }
  ]
}

При включённой галочке после прогона система сама собирает промпт для LLM: инструкции, шаблон отчёта и данные прогона.
